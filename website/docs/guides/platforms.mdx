# Platforms

| Platform | Support | Notes |
| --- | --- | --- |
| **Expo Go** | ✅ | No native code, so nothing to prebuild |
| **Expo dev builds / EAS** | ✅ | |
| **Bare React Native** (iOS, Android) | ✅ | `react-native >= 0.72` |
| **New Architecture** (Fabric) | ✅ | Uses only core components |
| **Hermes** / JSC | ✅ | `Intl` names fall back to English where unsupported |
| **React Native Web** | ✅ | This site runs the library on RNW |
| **Expo Router web / Next.js** | ✅ | Via `react-native-web` |
| **react-native-windows / macos** | Untested | Core components only, so likely to work |

## Why pure JS matters

- **Native feel, your brand.** Each platform gets its own [design](#designs), in your colors and fonts. Native date pickers change with every OS version, and Android's calendar dialog can't be themed much.
- **No native build.** Add the package and reload. Works in Expo Go and in OTA updates.
- **One code path.** No platform-specific bugs to chase, and tests run in Jest without native mocks.

## Designs

Pickers follow the design of the platform they run on: iOS on iOS, Material on Android, a web design on the web. A design changes shapes and layout, never your colors:

| | `ios` | `material` | `web` |
| --- | --- | --- | --- |
| Fields | label above, 48 tall | outlined, 56 tall; the label sits inside, then floats onto the border | label above, 40 tall, focus ring while open |
| Sheet corners | 24 | 28 | 12 |
| Cancel / confirm | beside a centered title, **Done** | after the content, **OK** | after the content, **Done** |
| Single select | ✓ beside the chosen option | a radio on every option | ✓ beside the chosen option |
| Option rows | rounded and tinted when chosen | edge to edge, untinted | compact, rounded and tinted |
| Date sheet | calendar | the picked date in large type above the calendar | calendar |
| Time | wheels | wheels | a list of times |
| Press | dims while held | ripple | dims while held |

Use one design on every platform with `design` on the provider, or set it on one component:

```tsx
<PickersProvider design="ios">
  <App />
</PickersProvider>

<SelectPicker design="material" options={options} value={value} onChange={setValue} />
```

`'auto'` (the default) picks iOS for `ios`, the web design for `web`, and Material for everything else. Your `theme` overrides and explicit props such as `confirmLabel` always win over the design, and a field passes its design to the sheet it opens.

## How it's built

Only React Native core APIs: `FlatList`, `Animated` (native driver on iOS/Android), `PanResponder`, `Modal`, `Pressable`, `TextInput` and `Intl`. No Reanimated, Gesture Handler, SVG or vector icons.

## Web specifics

- The wheel snaps to the nearest row once scrolling stops. Mouse wheel, trackpad and touch all work.
- `Modal` (used by sheets) renders into a portal on the web.
- Animations run on the JS driver on the web, because the native driver isn't available there.

### Previewing other platforms

Pickers adapt to `Platform.OS`: fields open a dropdown on the web and a bottom sheet on iOS and Android, sheets keep room for the iOS home indicator and status bar, and headers drag on native. To see the native behavior in a browser (a design system, Storybook, these docs), set `platform` on the provider:

```tsx
<PickersProvider platform="ios">
  <App />
</PickersProvider>
```

The switch on every live example here previews iOS, Android and Web this way, with each platform's [design](#designs). Other platforms, such as Windows and macOS, behave like Android.

### Next.js / SSR

Render pickers on the client. They measure layout and animate, so wrap them in a client component:

```tsx
'use client';
import { DatePicker } from '@elik56a/react-native-pickers';
```

and alias `react-native` to `react-native-web` in your bundler config (Expo's and Next's RNW guides cover this).

## Testing

Components render in Jest with the `react-native` preset. Use `testID` props to find them:

```tsx
render(<SelectPicker testID="country" options={opts} value={null} onChange={onChange} />);
```

Wheels settle with timers, so use fake timers (`jest.useFakeTimers()` + `jest.runAllTimers()`) when asserting on `onChange` after a scroll event.
